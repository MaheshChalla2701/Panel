Panel Interview Hub — Product Design & Technical Approach

Role: Senior Product Engineer • Platform: NIAT Panel • Scope: Round 1 Architectural Submission

1. Problem Understanding & Core Workflows

Panel is NIAT's premier skilling contest for engineering students. Participants progress across specialized tracks (AI Models Mastery, Applied GenAI, UI Engineering, Data Science) to earn Track Badges, which qualify top rankers on the Qualiflyer leaderboard for international immersion experiences. Prior to Interview Hub, badge interview scheduling was disconnected from contest progress: students were unsure when they became eligible, interviewers managed fragmented calendars without buffer periods, and operations admins lacked visibility into eligible candidates who dropped out before booking.

Panel Interview Hub resolves these issues through three tailored portals:

  • Student Experience: Live contest milestone audits, transparent eligibility status, atomic 45-minute slot reservation, safe rescheduling, and constructive candidate feedback inspection without exposing internal notes.
  • Interviewer Workspace: Weekly availability configuration, buffer-time enforcement, dedicated candidate dossiers with skill rubrics, attendance tracking, and immutable evaluation recording.
  • Admin Operations: Real-time conversion tracking, immediate unbooked student identification with one-click in-app reminders, interviewer workload balancing, and auditable malpractice investigation.

2. Student Interview Lifecycle & Multi-Dimensional State Machine

To prevent lifecycle corruption, the candidate journey is decoupled across five isolated state dimensions:

3. Edge Cases & Safety Policies

  • Double Booking Contention: Two students attempt to reserve the same slot simultaneously. Prevented by database unique exclusion constraints; second attempt fails gracefully with an actionable conflict alert.
  • Post-Booking Invalidation: Candidate contest is flagged after booking. Eligibility transitions to REQUIRES_ADMIN_REVIEW; interview is placed on administrative hold pending clearance.
  • Retake Cooldown Enforcement: RETAKE_LATER outcomes enforce a 7-day preparation pause before unlocking re-booking. Hard limit of 3 attempts per badge tier prevents session gaming.
  • Information Isolation: Private reviewer notes are cryptographically restricted to evaluator and admin scopes, strictly concealed from student API payloads.

4. PostgreSQL & Supabase Database Architecture

The architecture utilizes a normalized relational schema with PostgreSQL foreign keys, transactional triggers, and Row Level Security:

Table Name Primary Key Core Foreign Keys Indexes & Integrity Constraints
users id (UUID) — UNIQUE(email), CHECK(role IN ('STUDENT','INTERVIEWER','ADMIN'))
students id (UUID) user_id → users.id UNIQUE(student_code), INDEX(qualiflyer_rank)
interviewers id (UUID) user_id → users.id INDEX(active), CHECK(max_interviews_per_day > 0)
student_badge_journeys id (UUID) student_id, badge_id UNIQUE(student_id, badge_id), INDEX(eligibility_status)
interview_slots id (UUID) interviewer_id → interviewers.id UNIQUE(interviewer_id, start_at), CHECK(end_at > start_at)
interviews id (UUID) journey_id, slot_id, interviewer_id UNIQUE(slot_id) WHERE booking_status = 'BOOKED' (Double-booking lock)
interview_evaluations id (UUID) interview_id → interviews.id UNIQUE(interview_id) (Immutability guarantee)
malpractice_cases id (UUID) journey_id, reported_by, reviewer_id INDEX(status), Auditable decision history
audit_logs id (UUID) actor_id Append-only event log; records entity transitions & justifications

5. Key Architectural & Product Decisions

1. Decoupling Evaluation Outcomes from Badge Validity:
An interview outcome (PASS, FAIL, RETAKE_LATER) is an immutable evaluation of a technical conversation. Badge validity (AWARDED, UNDER_REVIEW, NULLIFIED, REINSTATED) is an institutional credential state. Separating these ensures that if malpractice is confirmed post-award, the candidate's interview record is never overwritten or deleted, preserving forensic truth.

2. Independent Historical Attempt Logging:
Every interview session generates a distinct row in interviews rather than updating previous rows in place. Evaluators assessing a retake candidate can review past technical deficiencies without destroying historical records.

3. Concurrency Protection & Double Booking Prevention:
To prevent race conditions when hundreds of candidates rush to reserve slots, the system uses filtered unique indexes on active slot reservations and atomic updates. If two requests collide, the second receives an instant conflict notification.

4. Evaluator Scoping & Permission Isolation:
Interviewers cannot view or modify peer availability, modify administrative policies, or award badges directly. Row Level Security policies enforce strict boundaries.

5. Unbooked Student Identification & Outreach:
The primary operational metric is the conversion gap between eligible students and confirmed bookings. The Admin table provides real-time filtering for Eligible & Unbooked candidates, with one-click in-app reminders to accelerate qualifying throughput.
